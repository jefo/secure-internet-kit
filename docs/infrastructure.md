# Infrastructure Strategy: Secure Internet Kit

## 1. Выбор VPS провайдера
Для микро-VPN сервиса критичны два фактора: чистота IP-адресов (чтобы они не были в спам-листах) и лояльность провайдера к VPN-трафику.

### Рекомендуемые провайдеры:
*   **Hetzner (Германия/Финляндия):** Отличное соотношение цена/качество. Строгие правила, но очень стабильные каналы.
*   **Netcup (Австрия/Германия):** Высокая пропускная способность, надежность.
*   **Aeza / Timeweb Cloud:** Хороши для работы в СНГ, есть локации в Нидерландах, Австрии, Турции. Оплата российскими картами.
*   **DigitalOcean / Linode:** Классика, но их IP часто попадают в списки "облачных провайдеров", которые блокируют некоторые стриминги.

## 2. Минимальные системные требования
TrustTunnel очень эффективен (написан на C++), поэтому нам не нужны мощные серверы.
*   **CPU:** 1 Core (достаточно для 20-30 активных клиентов).
*   **RAM:** 1 GB (минимум 512 MB).
*   **Disk:** 10-20 GB SSD.
*   **Network:** 1 Gbps port (минимум 100 Mbps).
*   **Traffic:** От 1 TB до безлимита (зависит от тарифа клиента).

## 3. География и задержки (Latency)
*   **Европа (NL, DE, FI):** Универсальный выбор. Хороший доступ ко всем мировым ресурсам.
*   **Турция / Казахстан:** Хороши для обхода локальных ограничений с минимальным пингом.
*   **США:** Нужны только для специфических сервисов (Hulu, локальный контент), высокий пинг из СНГ.

## 4. Сетевая безопасность (Hardening)
1.  **SSH:** Только по ключам. **Обязательно сменить порт 22 на нестандартный** (например, 2222). Порт 22 постоянно брутфорсят боты, что создаёт нагрузку и засоряет логи.
2.  **Firewall (UFW):** Открыты только порты SSH (нестандартный) и 443 (TCP/UDP).
3.  **Hiding:** TrustTunnel маскируется под веб-сервер. При обращении на IP сервера по HTTP(S) без VPN-запроса, сервер должен отдавать пустую страницу или 404 (настраивается в `reverse_proxy` настройках `vpn.toml`).

## 5. Доменная стратегия
Для работы TLS (HTTPS) необходим домен. 
*   Используйте нейтральные домены (.com, .net, .org, .me).
*   Избегайте слов "vpn", "proxy", "tunnel" в имени домена.
*   Пример: `cdn.web-assets-provider.com`, `api.cloud-services-sync.net`.

## 7. DNS-over-HTTPS (DoH)

Для защиты от DNS-слежки провайдера (ISP) шифрованные DNS прописываются прямо в конфиг клиента:

```toml
dns_upstreams = [
    "https://dns.adguard-dns.com/dns-query",
    "https://cloudflare-dns.com/dns-query",
    "https://dns.google/dns-query"
]

[listener.tun]
change_system_dns = true
```

Windows отправляет DNS-запросы внутри HTTPS-туннеля. Провайдер видит только зашифрованный трафик к VPN-серверу.

## 8. Обновление TLS-сертификатов

Certbot обновляет сертификаты автоматически, но TrustTunnel нужно «пнуть» через `SIGHUP`:

```bash
# scripts/renew_certs.sh
0 3 * * 1 /opt/trusttunnel/scripts/renew_certs.sh >> /var/log/trusttunnel/renew.log 2>&1
```

## 6. Selective Routing (Раздельное туннелирование)

### Режимы работы

#### `vpn_mode = "selective"`
Весь трафик идет напрямую через провайдера клиента. Только домены/IP из списка `exclusions` идут через VPN-туннель.
- **Плюс:** Максимальная скорость для обычных сайтов, банки работают.
- **Минус:** Нужно постоянно обновлять список заблокированных сайтов.

#### `vpn_mode = "general"` (Рекомендуемый для начала)
Весь трафик идет через VPN. Банки и госсервисы вносятся в `exclusions` для прямого доступа.
- **Плюс:** Надежная защита, работает всё заблокированное.
- **Минус:** Нужно знать список банков/локальных сервисов.

### Пример конфига (`selective_config.toml`):
```toml
vpn_mode = "general"
exclusions = [
    "sberbank.ru",
    "gosuslugi.ru",
    "tinkoff.ru",
    "avito.ru",
    "yandex.ru",
    "*.ru"
]
```
